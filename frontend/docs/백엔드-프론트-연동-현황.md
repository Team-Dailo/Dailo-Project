## 3. 백엔드만 있고 프론트 연동 없는 것 (관리자·기타)

| 백엔드 API | 용도 | 비고 |
|------------|------|------|
| `GET/POST/PUT/DELETE /api/admin/events` | 관리자 이벤트 CRUD | admin.service + 마이페이지 관리자 → 행사 관리 |
| `GET /api/admin/sync-logs`, `/{id}` | 동기화 로그 목록/상세 | admin.service + 관리자 → 동기화 로그 |
| `GET/POST /api/admin/reports`, `/{id}`, `/{id}/action` | 신고 목록/상세/처리 | admin.service + 관리자 → 신고 처리 |
| `GET /api/admin/ingest-logs`, `/{id}` | 수집 로그 목록/상세 | admin.service + 관리자 → 수집 로그 |
| `PATCH /api/admin/posts/{postId}/author` | 게시글 작성자 변경 | admin.service + 관리자 → 게시글 관리 |
| `GET /`, `GET /hello` | 테스트 | TestController |

### 관리자 계정 지정 (백엔드)

- **방법 1 (이메일):** `application.properties`에 `app.admin.emails=yunajo5858@gmail.com` 처럼 관리자 이메일을 지정. (쉼표 구분으로 여러 명 가능)
- **방법 2 (ID):** `app.admin.user-ids=1,2,3` 형태로 회원 ID를 지정.
- **동작:** 앱 기동 시 `AdminInitializer`가 해당 회원의 `role`을 `ADMIN`으로 설정. **해당 계정으로 로그인했을 때만** 마이페이지에 "관리자" 메뉴가 표시됨.
- **프론트:** `GET /api/auth/me` 응답의 `role`이 `ADMIN`이면 마이페이지에 "관리자" 섹션이 보이고, "관리자 메뉴"로 진입 가능.

## 5. 한 줄 요약

- **연결됨:** 인증, 게시판(목록/상세/작성/댓글), 이벤트(캘린더/지도/상세), 스크랩, 로그(검색·클릭), 신고, 차단(하기), 채팅(방 목록/방/메시지 조회/나가기/방 만들기).
- **더 쓰면 좋은 API:** 클릭 수·인기 클릭 이벤트, 내 신고/차단 목록, 차단 해제·차단 여부 확인, **홈 행사 리스트**(`GET /api/events`), 게시판 검색, 게시물/댓글 수정·삭제.
- **백엔드만 있음:** 관리자(admin) 전부, 테스트(hello).
- **아직 없음:** 채팅 메시지 전송(실시간은 STOMP), 검색 결과 페이지 연동.
